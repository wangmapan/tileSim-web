# TileSim Web 第五批：总览与网络页首屏重构

日期：2026-09-07。用户指出前几轮变化不明显，本批改为可直接感知的首屏布局重构，而非继续调整局部边框。范围仅为前端展示，不改变仿真架构、接口或证据语义。

## 1. 基线与工作边界

- 当前浏览器实际位于 4173 的网络与通信页，并非旧版 5173；不能把视觉变化不明显归因于用户看错预览。
- 先检查启动卡、交接、相关代码与已有 diff。当前中文模块术语优先于前端启动卡中的旧编号约定。
- 本地 main 与已跟踪 origin/main 的 ahead/behind 为 0/0；没有 fetch 或提交。
- 保存修改前工作树 patch、状态和相关文件原文：`runtime/visual-review/batch5/baseline/`。保留之前各批与其他工作流的未提交改动。
- 修改前读取已存在的“测试用例1”，保存两页 × 三宽度（1100/1440/1920）× 两主题共 12 张截图：`runtime/visual-review/batch5/before/`。
- 不修改后端、前端仓库内 Bridge 实现、接口、路由、启动脚本；不停止、重启或替换 5173 服务。不新建真实运行，不调用真实 Evidence Agent Provider。
- 4173 是源码预览；生产构建只写入忽略的 dist，不等于部署到 5173。

## 2. 按优先级审查与方案

| 优先级 | 问题                                           | 本批处理                                                                                                                      |
| ------ | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |

| P2     | 主瓶颈位于总览下方，与运行结论脱节             | 将原有瓶颈结论与运行主指标并列，不重新计算或猜测瓶颈                                                                          |
| P2     | 总览只有通用统计，缺少网络观测                 | 显示报告中前 6 个通信域的占用对照；固定 0–100% 尺度，保留报告顺序，不制造拓扑或排序                                           |
| P2     | 网络页三个等权指标不能说明先看什么             | 最长通信等待成为主指标，占用和域数量为辅助观测；主导域、等待类型、事件数和精确观测窗口放在并列证据区                          |
| P2     | 首屏容器同质化，主要结论与普通区域视觉权重相同 | 采用实色深青灰主指标区和主题适配的中性证据区；下方使用分隔线与对齐，不增加重复卡片                                            |

实施前已向用户输出上述问题与方案。此次明显增加的是结构对比和真实数据表达，不是装饰数量。

## 3. 调研依据与素材许可

复用上一批已成功读取的 10 个官方来源，完整来源链接、逐项借鉴点、不照搬内容与许可记录见 [第四批调研](FRONTEND_ATTRIBUTION_RESEARCH_2026-09-07.md#2-本次联网参考与素材记录)。本批没有声称重新完整浏览了 10 个产品，也没有将旧截图称为最新界面。

本批具体采用：

- Linear、Primer：加强主次关系、连续对齐和分隔线，避免相似卡片占满工作区。
- Nsight、Ray、OpenSearch：先明确观测对象与范围，再进入现有执行、网络和证据页面；不将仿真记录伪装成硬件实测。
- Grafana：固定量纲和范围，文本数值与条长一致；不自动拉伸 min/max，不加入未经报告的阈值。
- W&B、Stripe：摘要与可审计详情分层，保留实验上下文；不引入营销式 hero 或“健康评分”。
- Jaeger、Notion：保留现有分析入口和按需展开，不把公开 trace 工具的实体层级移植成 TileSim 新架构。

没有使用第三方图片、标志、截图、字体或新增图标库；没有取得这些素材的再分发授权，也没有将它们加入产品。新增视觉实现为原生 HTML/CSS 和现有 Lucide 图标。

## 5. 数据与性能边界

- 占用条只对有限且位于 [0, 1] 的值绘制。0 是零宽；缺失和越界没有条，显示文本仍保留 `—` 或原值，不画成健康或正常。
- 总览只对报告数组做 `slice(0, 6)`，不扫描、汇总、排序或按利用率推测瓶颈；无逐域数据时显示明确缺失说明。
- 网络页现有 25 条分页、按需详情和 ECharts 生命周期不变。新增 DOM 上限固定，无持续动画、监听器、定时器、大阴影、blur 或运行时依赖。
- 原始整数仍由既有无损格式化函数显示。没有改写 report、Trace provenance、校准、完整度、SHA 或 Pointer。
- 单元与浏览器测试不构成实机校准、独立验证或保真度证据；页面仍显示探索性边界。

## 7. 审美检查与后续

- 去掉深色底仍可通过 DOM 顺序、字号、列宽和分隔线识别主指标与证据。
- 两页共享规则，不共享一套虚构数据或通用营销文案；没有渐变、发光、玻璃、网格、粒子、装饰连线或额外迷你图。
- 总览只有运行摘要和真实网络域对照两个重点；网络页以等待与后端主导域为重点。颜色不代表新增告警判断。
- 中英文长内容可以换行；1100px 仍为桌面双栏，小于 980px 的桌面窗口改为单列，不增加移动端产品范围。
- 后续可针对执行过程优化时间轴与依赖阅读，对新建实验改善配置对照；不机械铺开相同深色面板。入口主 chunk 的既有体积告警仍需独立性能拆分工作。
