## 审查结论

修复后未发现仍开放的 P0/P1 问题。F2 继续维持 `validated（frontend compatibility scope）`，但后端 canonical JSON Schema 缺失仍是 external blocker。

| 级别 | 发现                                                                                                           | 处理                                                                                                     |
| ---- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| P1   | API root fallback 会重放 POST；首个请求若已经创建运行但响应丢失，可能重复执行                                  | 非 GET 请求固定只发送一次；仅 GET transport failure 可切换 fallback root，并新增回归测试                 |
| P1   | 缺失字段读取整个 bundle 的任意 resolution entry，S0 expected absence 可把缺失的 S1 指标误标为 expected absence | availability 按报告种类和相关 subsystem 计算；无相关显式声明时保持 `missing`                             |
| P1   | unversioned legacy 报告完全绕过形状检查，畸形 run 可进入组件并触发运行时错误                                   | legacy 保持兼容，但 run/design-space/execution-envelope 及可选数组先做最小安全形状检查，畸形输入失败关闭 |
| P2   | 负的 S7 stage duration 被钳制成真实数值 `0`                                                                    | 负时间差显示为无效，不再与真实零时长混淆                                                                 |
| P2   | `decode_step_count`、`score_ps` 依赖宽泛索引签名，未进入显式类型                                               | 补入报告模型；页面继续通过 TypeScript 检查                                                               |
| P2   | `has_tail_attribution` 缺失时显示“未生成”，与明确的 `false` 混淆                                               | 缺失或不适用显示“不适用”，仅 available 值显示已生成/未生成                                               |

## 仍保留的技术债

- 报告模型仍允许 additional properties，以保留前向兼容和完整原始证据；F4 应通过 adapter/view model 依赖规则进一步阻止页面读取未声明字段。
- 当前 schema 是前端兼容材料，不是后端 canonical contract。
- Router、Pinia、TanStack Query、目录迁移和单体 CSS/bridge 拆分仍属于 F4，不在本次审查中提前实施。
