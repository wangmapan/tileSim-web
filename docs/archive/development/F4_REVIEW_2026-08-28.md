# F4 Review 与优化

**日期**：2026-08-28  
**范围**：F4 模块边界、缓存 identity、导航并发和 Bridge 工件恢复

## Review 结论

| 严重度 | 发现                                                                                 | 优化                                                                              |
| ------ | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| P1     | completed run 的损坏可选 JSON 会让 reports endpoint 抛异常；损坏主报告没有结构化失败 | repository 忽略损坏的可选报告；缺失/损坏主报告返回 `primary_artifact_invalid`     |
| P1     | CLI 终态更新和 run 重命名可能并发覆盖 metadata 字段                                  | 独立 `metadata_lock` 串行化 metadata read-modify-write                            |
| P1     | 较早的 run 导航请求可能在 `finally` 中提前清除较新请求的 busy 状态                   | busy 只由当前 synchronization revision 清除，并新增竞态单测                       |
| P2     | feature/store 反向导入 `app/providers`，模块拆分后仍存在高层依赖                     | Pinia 实例迁入 `stores/pinia.ts`，QueryClient 迁入 `lib/query-client.ts`          |
| P2     | `lib/execution.ts` 兼容 facade 形成 `lib -> feature` 反向边                          | 测试改用 execution-inspector 公共入口并删除 facade                                |
| P2     | 本地 snapshot 在 Git revision 相同但 state digest 不同时可能复用旧 Query key         | backend cache identity 纳入 source/build revision、state digest 和 deployment ref |
| P3     | 两个 comparison run 在启动恢复时串行加载                                             | 改为并行加载并保持选择顺序                                                        |

## 自动防回退

- `deps:check` 新增 `features`、`lib`、`store`、`stores` 的高层反向依赖限制。
- 架构边界仅约束生产源文件；测试仍参与循环检测，但可通过公共入口测试高层模块。
- Bridge 新增 malformed optional artifact 和 malformed primary artifact 测试。
- 前端新增快速 run 切换 busy-state 竞态测试。
