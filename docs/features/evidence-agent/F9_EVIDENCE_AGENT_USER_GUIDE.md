# Evidence Agent 使用指南

> 适用范围：TileSim Web 当前的 Evidence Agent 页面（F9）。
>
> 当前结论：它是“基于已完成实验的单轮证据解释器”，不是一个可以自由聊天、记住上下文或替用户运行实验的通用 Agent。

## 1. 它能帮你做什么

Evidence Agent 读取当前实验中已经验证、可以精确引用的结果，再生成一份解释草稿。它不会修改原始实验结果，也不会自行运行新的模拟。

当前 descriptor 最多声明四类任务：

| 页面选项           | 适合问什么                                  | 示例问题                                                          |
| ------------------ | ------------------------------------------- | ----------------------------------------------------------------- |
| 看懂 P99 请求      | 解读后端已经标出的 P99 请求及其证据         | “请用通俗语言解释这个请求的 P99 表现，以及报告中有哪些直接依据。” |
| 看懂尾延迟         | 解读当前请求的尾延迟表现和报告中已有的依据  | “这个请求的尾延迟表现应该怎样理解？”                              |
| 判断结果可信度     | 说明数据来源、验证情况、fidelity 和适用限制 | “这份结果有多可信，可以支持哪些判断？”                            |
| 寻找下一步优化方向 | 根据已有证据整理下一步值得验证的方向        | “基于当前证据，下一步最值得验证哪些优化方向？”                    |

这不是四个固定问题。选择其中一类后，用户仍然可以在问题框中自由修改问题；只是问题必须属于所选任务类型，而且只能由当前实验的可引用证据回答。

后端 descriptor 是能力真源。以后如果 descriptor 只声明其中一部分，页面也只会显示后端正式支持的那些任务，不会自行补出新能力。

## 2. 开始前需要什么

使用前需要同时满足：

1. 已完成一次 TileSim 实验，而不是只打开示例数据。
2. 当前实验生成了受支持的正式 `metrics` 等证据产物。
3. Bridge 已连接并公布兼容的 Evidence Agent descriptor。
4. Provider 配置完整，认证探测通过，页面显示“可以开始提问”。

如果页面显示“先运行一次实验”，点击“重新运行实验”，完成实验后再回到 AI 解释页面。

如果页面显示“AI 解释当前不可用”，说明当前没有通过能力检查的模型服务。此时仍可查看普通实验报告，但不能生成 Agent 解释。

### 配置模型服务

推荐双击无控制台黑框的单文件 GUI 启动器
`D:\tileSim-team\05-tools\启动TileSim工作台.exe`，在“大模型服务设置”中填写：

- OpenAI 兼容 Base URL；
- 服务返回的精确模型名；
- API Key；
- 请求超时。

首次配置必须填写 Key；之后只修改 Base URL、模型名或超时时，可以让 Key 保持为空以继续使用已保存
的值。Key 使用 Windows DPAPI 按当前用户和电脑加密，保存在被 Git 忽略的本地 runtime 配置中，
不会进入浏览器、命令行参数或仓库。保存后点击“启动 / 重启并打开”使设置生效。HTTPS 可用于远程
服务；明文 HTTP 只允许 localhost 或其他 loopback 地址。

## 3. 实际使用步骤

### 第一步：选择请求

在“1. 选择要解释的请求”中选择一个 request。Agent 的输入和引用都会绑定到这个 request 以及当前 run。

如果你是从 P99 或慢请求页面进入，优先选择报告已经标出的目标 request。不要仅凭 request ID 猜测哪个请求是 P99；P99 身份以报告中的正式 percentile subject 为准。

### 第二步：选择想了解的内容

在“2. 选择你想了解的内容”中选择一种任务。页面只展示当前 descriptor 声明支持的任务。

### 第三步：确认问题

问题框会给出与任务匹配的推荐问题：

- 推荐问题符合需求时可以直接使用；
- 想关注某个具体现象时，可以改成自己的问题；
- 切换任务会更新尚未编辑的推荐问题；
- 已经手动编辑过的问题不会被页面覆盖。

问题应尽量具体，例如“这个请求的长尾主要有哪些已报告依据？”，不要问“帮我全面优化系统”这类需要新实验、外部知识或未声明工具的问题。

### 第四步：提交前确认

提交前确认区会显示：

- 当前 request；
- 可引用的精确证据位置和 artifact 数量；
- 数据来源及可信范围；
- requested fidelity、resolved fidelity 和 execution mode；
- 本次同步等待的服务上限。

这里如果显示“证据可信范围尚未就绪”或可引用证据为 0，不要提交；先检查实验是否成功生成正式证据。

### 第五步：生成并阅读解释

点击“生成解释”后等待当前同步请求结束。结果优先按以下顺序展示：

1. 结论；
2. 依据；
3. 限制；
4. 下一步。

每条重要结论都应能展开“查看依据”，并跳到原始 artifact 的精确位置。需要复现或审计时，再展开 SHA-256、JSON Pointer、subject、schema 和模型 revision 等专业详情。

Agent 结果是待确认草稿，不能覆盖确定性报告。遇到 `partial`、`refused` 或 `truncated` 时，只使用页面明确展示且带有效引用的部分，不要把它当成完整回答。

## 4. 它接的是什么模型

前端没有写死 GPT、Claude、DeepSeek 或其他具体模型，也不会从浏览器直接连接模型厂商。

调用链是：

```text
TileSim Web
  -> TileSim Bridge Evidence Agent API
  -> Bridge 配置并认证的 Provider / model
  -> Bridge 校验结构化 response 和 citations
  -> 前端展示通过校验的 atomic claims
```

实际使用的 `provider_id`、`model_id` 和 `model_revision` 由 Bridge 的 descriptor 公布。可以在页面底部展开“服务版本与模型详情”查看；结果生成后，结果详情也会记录实际返回的 Provider/model identity。

截至 2026-09-02，仓库记录的 5173 环境已经通过 authenticated capability probe，正式状态为
`availability=available`、`configured=true`；但 live model repetitions 仍为 0。能力探测通过只表示当前
Provider/model identity 可调用，不等于已经完成 live success/refusal/timeout、安全重复评测或双人 citation
entailment review，因此 F9 仍是 acceptance-pending。

## 5. 它现在能连续对话吗

不能。当前契约是 `synchronous_terminal`：一次提交对应一个不可变的、绑定当前 run/request/snapshot 的单轮分析。

当前不支持：

- 在上一条回答下面继续追问并继承上下文；
- Agent 主动向用户提出澄清问题，再等待用户补充；
- 保存长期聊天记录或分析历史；
- 跨 run 对话或比较多个 run；
- SSE 流式输出和异步取消。

用户可以重新填写问题并发起另一份分析，但它是新的独立请求，不会自动记住上一轮回答。若页面显示旧分析、stale 或 409 锁定状态，需要用户明确点击放弃后，页面才能创建新分析；系统不会静默换 key 或再次调用 Provider。

真正的多轮对话需要 Bridge 先发布包含 conversation/session identity、turn ordering、每轮 snapshot/citation 绑定和留存规则的新版本契约。当前前端不会用本地聊天历史伪装这一能力。

## 6. 它不会做什么

Evidence Agent 当前不会：

- 重新计算或自行选择一个新的 P99；
- 把 S3、S4、S5 排成虚假的线性因果链；
- 把 S7、S8、S9 当作新的延迟原因进行排名；
- 把 synthetic trace 说成真实硬件或 held-out real-trace 验证；
- 根据模型猜测补造、合并或改写前端结论；
- 浏览任意网页、执行 shell、读取任意文件或访问任意路径；
- 自动执行优化建议并声称性能已经改善；
- 在浏览器中保存 Provider credential、raw response、问题正文或模型 hidden reasoning。

因此，它更适合回答“现有报告已经说明了什么、证据在哪里、结论有什么限制、下一步应该验证什么”，不适合替代模拟器、搜索工具或通用聊天助手。

## 7. 常见状态怎么处理

| 页面状态               | 含义                                             | 用户操作                                 |
| ---------------------- | ------------------------------------------------ | ---------------------------------------- |
| 可以开始提问           | run、request、证据和服务均已就绪                 | 选择任务，确认问题后生成                 |
| AI 解释当前不可用      | Provider 未配置或能力探测未通过                  | 查看技术原因，联系部署者检查服务         |
| 部分结果               | 只有部分 claims 通过并完成                       | 只使用已展示且有引用的内容               |
| 已拒答                 | 当前证据不足或问题超出边界                       | 缩小问题范围，检查证据是否齐全           |
| 输出已截断             | Provider 输出达到上限                            | 不把当前结果当成完整回答                 |
| 结果已过期             | run、backend、schema revision 或 snapshot 已改变 | 明确放弃旧分析，再基于当前结果重新提问   |
| 上次结果无法恢复       | Bridge 重启后没有保留 claims-bearing 结果        | 明确放弃旧分析；系统不会自动重新调用模型 |
| 当前问题与上次提交冲突 | 同一个 key 对应了不同 payload                    | 明确放弃旧分析，再创建新问题             |

## 8. 一句话判断

如果你的问题可以改写成“请根据当前实验中可引用的证据，解释这个 request 的某个已有结果”，它适合交给 Evidence Agent。

如果问题需要新的模拟、外部资料、多轮澄清、跨 run 记忆或执行操作，当前版本就不支持。
