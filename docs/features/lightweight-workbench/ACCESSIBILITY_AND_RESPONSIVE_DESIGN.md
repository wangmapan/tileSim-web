# 无障碍与响应式设计（电脑网页端）

产品范围只包含桌面网页端；这里的响应式是为了不同桌面窗口和浏览器缩放，不扩展移动端实现或验收。

## 1. 键盘与焦点

- `/` 首屏焦点顺序：跳过链接 → 专业版入口 → 轻量版入口 → 模式/帮助。
- 任务卡使用原生 `button`/`a`，Enter/Space 可触发；不可用动作仍可聚焦并说明原因。
- Agent 输入支持 Tab、提交、清除、展开详情；提交后焦点移至状态摘要或错误区域。
- 对话/详情展开不抢焦点；Escape 关闭临时层并返回触发控件。
- Focus ring 与主题 token 一致，不能只靠颜色或阴影表达。

## 2. 语义与读屏

- 页面只有一个 `h1`；工作区、理解摘要、限制、下一步使用 `section`/`h2`。
- 草案、未运行、示例、stale、unsupported、error 使用文字 + `aria-live`/`role=alert`，不只用颜色或图标。
- 状态列表使用可读的 label/value；单位、来源、revision 与值绑定在同一语义组。
- `details/summary` 或等价控件必须有明确展开名称，如“查看 schema revision 和 Pointer”。
- 任务卡的“预计耗时、是否只读、完成后得到什么”在可访问名称中可读。

## 3. 视觉与缩放

- 200% 浏览器缩放下仍可完成入口、任务选择、输入和切换；不出现横向滚动。
- 关键正文行高 ≥1.5，控件目标尺寸 ≥44×44 CSS px（桌面指针和键盘均可操作）。
- 颜色对比至少满足 WCAG 2.2 AA；状态同时有图标/文字。
- 尊重 `prefers-reduced-motion`，禁止用动画传达唯一状态。

## 4. 桌面断点

| 窗口宽度 | 布局 |
| --- | --- |
| ≥1280 | 任务卡 2×2 或主任务 + 辅助列；理解/下一步可并排 |
| 900–1279 | 主内容单列，摘要详情可折叠；模式切换仍在顶栏 |
| 700–899 | 轻量 shell 保持导航文字，三栏改纵向；不进入移动端专属实现 |
| <700 | 仅保证基础可读和无横向溢出；作为桌面窄窗回退，不新增移动导航 |

## 5. 测试要求

Playwright fixture 覆盖 800×600、1024×768、1440×900、200% zoom、键盘焦点、深浅主题、reduced-motion、axe serious/critical 和无横向溢出。每个状态至少有人工读屏抽查一次。
