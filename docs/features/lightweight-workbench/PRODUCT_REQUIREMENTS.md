# 产品需求：并列双工作台

## 1. 产品问题与目标

TileSim 当前能力丰富，但新用户必须先理解模型、设备、并行、KV、带宽和 SLO 等术语，才能开始。目标是把“我想知道/比较/准备什么”转成可理解、可追溯的下一步，同时保持专业用户的效率和现有证据边界。

### 成功定义

1. 用户进入 `/` 即看到两个同等权重的工作台入口，不需要先进入专业版再寻找轻量版。
2. 新手在 3 分钟内能完成一次“选择目标 → 描述问题 → 看懂 Agent 理解 → 发现缺口/获得草案 → 知道下一步”的首次成功路径。
3. 轻量版解释每个关键字段的用途、单位、来源、是否已确认和为什么缺失；不掩盖限制。
4. 专业版原有深度和 URL 可用性不回归；用户能在两种工作台间切换而不丢失当前 run 或草案上下文。

## 2. 用户与场景

| 用户 | 经验 | 主要任务 | 需要突出 |
| --- | --- | --- | --- |
| 入门学习者 | 不熟悉仿真术语 | 了解概念、准备第一个配置 | 术语解释、示例、进度、下一步 |
| 方案评估者 | 了解业务目标，技术细节有限 | 比较配置方向、理解结果 | 目标/结论、假设、可信范围、限制 |
| 仿真工程师 | 熟悉 S0-S9、运行和证据 | 精确编辑、运行、审计 | 完整表单、原始值、revision、证据链 |
| 评审/管理者 | 关注结论和风险 | 查看摘要与可追溯依据 | 结论、证据状态、风险、导出入口 |

## 3. 范围

### 必须包含

- 主页工作台选择页（专业版/轻量版并列卡片）。
- 轻量版独立 shell：任务首页、概念/场景、Agent 交互、理解摘要、限制与下一步。
- 专业版独立 shell：保留现有完整导航和页面。
- 顶部模式切换器、浏览器后退、刷新、深链接和可选的最近模式记忆。
- 轻量版对 `unknown`、`missing`、`unsupported`、`stale`、`validation error`、Bridge unavailable 的友好解释。
- 可从轻量结果跳转专业详情，并保留同一 run/上下文引用。

### 明确不包含

- 移动端布局或移动端验收。
- 新的模型调用、多轮 Conversation、RAG、Workflow、审批、自动执行。
- 在轻量版创建正式 simulation run 或直接调用 Provider。
- 重新计算模拟指标、推断缺失值、改变 fidelity/provenance。
- 将轻量版做成专业版的隐藏 tab、缩小字体或“简化皮肤”。

## 4. 核心产品原则

1. **并列而非从属**：两张入口卡片拥有相同视觉权重；切换是一级操作。
2. **先目标后参数**：先问“你想完成什么”，再逐步暴露字段。
3. **结论先行、证据可展开**：默认显示目标、当前结论、可信范围和下一步；技术细节通过展开层获取。
4. **状态诚实**：`0`、missing、expected absence、not covered、unsupported schema、not applicable 保持区分。
5. **每一步可撤销**：草案是内存态；确认前不会改写实验表单或创建 run。
6. **学习与工作相连**：术语解释必须链接到当前字段/任务，而不是独立百科。

## 5. 关键指标（首版基线）

- 入口可发现性：首次访问用户能在首屏看到两个入口，目标 100%。
- 首次成功完成率：从 `/` 进入轻量版并得到“理解摘要/澄清/限制”结果，目标 ≥80%。
- 误解率：用户把草案当成已运行结果的比例，目标为 0（文案和状态测试阻断）。
- 入口切换成功率：携带 run 的深链接切换后 run ID 不变，目标 100%。
- 专业版回归：现有关键路线和测试全通过。
- 可访问性：严重/关键 axe 问题为 0，200% 缩放无横向滚动。

## 6. 发布决策门

只有当产品负责人确认本目录方案、设计评审确认入口/信息架构、工程评审确认 Agent 边界后，才进入 `IMPLEMENTATION_PLAN.md` 的 Phase L1。任一 Agent 能力 Gap 未关闭时，界面必须保持 fail-closed。

## 8. 角色与权限矩阵

| 能力 | 入门学习者 | 评估者 | 仿真工程师 | 评审者 |
| --- | --- | --- | --- | --- |
| 选择工作台 | 允许 | 允许 | 允许 | 允许 |
| 阅读概念/示例 | 允许 | 允许 | 允许 | 允许 |
| 提交单轮草案 | 允许 | 允许 | 允许 | 允许 |
| 查看 run 摘要 | 有权限的 run | 有权限的 run | 有权限的 run | 有权限的 run |
| 修改专业参数 | 引导进入专业版 | 允许 | 允许 | 取决于现有权限 |
| 创建/执行 run | 轻量首期禁止 | 遵循专业版权限 | 遵循专业版权限 | 遵循专业版权限 |
| 查看证据详情 | 摘要 + 可展开 | 摘要 + 可展开 | 完整 | 只读完整/摘要依权限 |

轻量版不能绕过现有 Bridge 或 workspace 权限；“能看到按钮”不等于“有权执行”。

## 9. 非功能需求

- **性能**：选择页首屏不依赖 capability 请求；首个可交互目标 ≤2 秒（本地开发基线，具体以现有 Web 性能预算为准）；能力请求失败不阻塞静态任务/学习内容。
- **可靠性**：刷新/后退不破坏合法 URL；重复提交不会创建 run；上下文 revision 不匹配时 fail closed。
- **可维护性**：view 只编排；feature 通过公开 `index.ts`；UI 组件不访问 store/Bridge/schema。
- **国际化**：中文和英文的状态、错误、按钮语义对齐；不可把英文 fallback 当作缺失状态。
- **安全**：遵循 [SECURITY_RETENTION_AND_FAILURE_SEMANTICS.md](SECURITY_RETENTION_AND_FAILURE_SEMANTICS.md) 的 redaction 和 retention 规则。

## 10. 边界案例（必须有设计）

1. 用户从旧 `/overview` 收藏链接进入：显示专业版，不强制轻量版。
2. 用户从无效 `run` 深链接进入：显示不可用原因，不创建空 run。
3. capability snapshot 在提交前变 stale：拒绝提交并要求刷新。
4. 用户重复点击提交：按钮进入 pending，结果只接受一次，不能产生多条伪对话。
5. 用户在轻量版打开专业版新标签：两个标签的模式偏好不覆盖 run-bound 状态。
6. 用户关闭页面：说明单轮草案可能丢失，不能暗示已保存。
7. 浏览器禁用 localStorage：选择仍可用，偏好仅退化为本次会话记忆。
