# 轻量工作台体验设计

## 1. 体验定位

轻量版的任务不是“少几个参数”，而是把用户从目标带到可理解的决策材料。它默认隐藏实现细节，但不隐藏事实、来源和风险；用户始终可以进入专业版查看完整技术页面。

核心循环：

```text
选择目标 → 说出问题 → Agent 复述理解 → 补充/确认 → 结果摘要
                                  ↘ 缺口/限制 → 学习或进入专业版
```

## 2. 主页：工作台选择

`/` 是独立的选择页，不自动把用户送入专业版（仅在用户明确记住模式时可按偏好跳转，仍提供“切换工作台”入口）。

- 顶部：TileSim 标识、语言/主题、帮助；不出现技术导航噪音。
- 主标题：“选择适合你的工作台”。副标题说明两者共享同一仿真事实，但操作方式不同。
- 两张等宽卡片：
  - **轻量版**：目标导向、逐步解释、适合刚开始；按钮“进入轻量版”。
  - **专业版**：完整参数、运行与证据、适合精确控制；按钮“进入专业版”。
- 卡片下方：不确定时先选轻量版；“以后可随时切换”。
- 最近模式记忆只能是非敏感偏好；首次访问不预选，避免用户错过选择。

## 3. 轻量版页面结构

轻量版有自己的 shell 和导航，不复用专业版侧栏。

### 3.1 任务首页（默认页）

首屏只突出一个主任务和三个辅助任务：

1. **我想先了解 TileSim**：用 3 张概念卡解释“输入—模拟—结果”。
2. **我想准备一个配置草案**：以自然语言描述目标，生成八字段草案或澄清。
3. **我想读懂已有结果**：选择已有 run，先看结论和可信范围。
4. **我想看示例**：从模板开始，模板明确是示例，不代表真实校准。

每张任务卡包含：适用人群、预计耗时、是否只读、完成后得到什么。卡片不是直接启动隐藏流程。

### 3.2 Agent 工作区

采用“问题—理解—下一步”三栏层级（窄屏时纵向排列）：

- 问题区：textarea、示例提示、清除按钮；提示用户可用自然语言，不要求术语。
- 理解区：按字段显示“我理解为… / 还不确定… / 需要你确认…”，每项含原值、规范值、单位、来源和状态。
- 下一步区：确认草案、补充信息、查看解释、进入专业版。所有动作明确是否会创建 run（首版均不会）。

### 3.3 结果摘要

默认顺序固定为“结论 → 依据 → 限制 → 下一步”：

- 结论：仅显示 canonical 结果或 Agent 解释，不生成新指标。
- 依据：artifact/run/schema/revision/Pointers 等可追溯信息。
- 限制：数据缺失、unsupported、stale、synthetic 或未覆盖必须单独列出。
- 下一步：补充字段、打开专业版、学习相关概念；不可用动作置灰并解释原因。

“查看技术详情”使用渐进披露（`details` 或等价语义控件），不会把专业表单嵌进轻量页面。

## 4. 首次成功路径（P0）

示例：用户输入“我想看看 batch 调大到 8 会怎样”。

1. 在主页选择轻量版。
2. 点击“准备一个配置草案”，看到输入提示与示例。
3. 输入自然语言并提交；显示“正在确定性解析”，不得显示模型正在运行。
4. Agent 复述：识别到 `max batch size=8`，其他字段未提供；列出需要补充或保持当前值的字段。
5. 用户看到“草案，尚未创建运行”徽标，可展开字段来源/单位。
6. 用户选择“补充信息”或“进入专业版”；切换后 run ID、草案 revision（如存在）不被伪造或丢失。

错误与缺口也算可完成路径：页面必须告诉用户发生了什么、能否重试、需要谁处理，以及不会产生什么副作用。

## 5. 教学与模板

- 概念卡每次只介绍一个词：一句白话、一个 TileSim 关联、一个“为什么重要”、一个“深入专业版”链接。
- 模板按目标而非参数分类：吞吐优先、延迟优先、资源受限、结果解读。模板内容标注 `example`，不冒充真实能力或校准。
- 首次引导最多 3 步，可跳过；跳过后可从帮助入口重开，不把引导状态写入 Agent/context。

## 6. 专业版衔接

衔接是“查看/继续处理”而不是“升级账户”：

- 轻量摘要提供“在专业版查看”链接，目标路由可带 `run`、artifact SHA 和 schema revision 查询参数。
- 专业版展示完整导航和原有表单；若上下文 stale，明确锁定旧 key，要求用户显式丢弃或重新开始。
- 返回轻量版时保留当前工作台偏好，不清除 run-bound 状态，不覆盖专业版表单。

## 7. 文案和视觉层级

- 主按钮只使用动作 + 对象：“准备草案”“查看结果”“进入专业版”。
- “草案”“未运行”“示例”“不可用”必须与标题同层级可见，不放在 tooltip 内。
- 颜色不是唯一状态编码；配合图标、文字和 `aria-live`。
- 轻量版沿用 TileSim 设计 token，但使用更宽松间距、更少并列控件和更短段落；不另造一套品牌。

## 8. 页面状态细化

### 8.1 选择页状态

- **首次访问**：两卡等权，不显示“推荐专业版”；可在轻量卡显示“适合第一次使用”。
- **最近使用**：只显示弱提示“上次使用”，不改变卡片尺寸、排序或 CTA 权重。
- **Bridge 离线**：选择页仍可进入两种模式；卡片下提示“运行能力需要本地 Bridge”，不阻塞学习内容。
- **浏览器存储不可用**：入口正常，隐藏“记住选择”反馈。

### 8.2 轻量空状态

- 没有 run：优先显示“准备草案/学习/示例”，结果任务解释需要先选择已有运行。
- 有 run 但报告未加载：展示 run identity 和载入状态，保留返回/切换入口。
- 没有 capability：输入区保持只读或禁用，显示原因和可用的学习路径。
- 草案已丢失：显示“草案未保存”而不是空白；允许重新开始。

### 8.3 等待状态

等待提示必须说明正在做什么和没有做什么：

- `正在读取可用能力`：未提交指令；
- `正在确定性解析你的描述`：未调用外部模型，未创建运行；
- `正在读取已有运行结果`：只读，不重新运行；
- 超过 2 秒显示可取消/返回；超过现有 timeout 显示稳定错误码和重试。

### 8.4 成本、权限与副作用

首期轻量操作成本标记为“本地只读/无外部模型调用”。若进入专业版可能运行仿真或调用 Evidence Provider，必须在专业动作处重新显示成本、权限和确认；轻量版不能替专业版提前授权。

## 9. 结果可信度卡

结果摘要固定包含一张“你可以信任到什么程度”卡片：

1. 数据来源：真实、合成或 compatibility；
2. schema/backend identity 与更新时间；
3. requested/resolved fidelity；
4. 已覆盖和未覆盖的 subsystem；
5. 影响结论的 missing/unknown/stale；
6. 跳转到专业证据详情的链接。

该卡片不能用单一“可信度百分比”替代，因为当前契约没有这种指标。

## 10. 典型用户旅程

### 了解概念

选择“我想先了解” → 看到输入/模拟/结果三步 → 点开与当前任务相关术语 → 返回任务首页。全程不需要 Bridge。

### 准备草案

选择“准备配置” → 输入自然语言 → Agent 复述字段 → clarification/validation → 草案摘要 → 进入专业版继续；首期不把草案自动写入专业表单。

### 解读结果

选择已有 run → 先看结论和限制 → 展开依据 → 必要时进入对应专业页；不能基于缺失字段生成新结论。

### 浏览示例

按任务选择模板 → 查看预置输入和预期界面状态 → 用户显式复制到输入区 → 仍走正式 compiler；模板输出不能作为 live evidence。
