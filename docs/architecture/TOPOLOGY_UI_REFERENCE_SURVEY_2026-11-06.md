# 拓扑与仿真工作台网页设计调研

日期：2026-11-06  
范围：电脑网页端；用于 TileSim 实验设置、拓扑编辑、互联参数和执行回放的页面设计决策。

## 结论先行

成熟的网络实验和仿真工具通常遵循一个稳定分层：

1. **画布表达关系和空间结构**：节点、组、链路、路径和当前选择。
2. **清单表达精确对象**：节点 ID、类型、所属计算组、端点、状态和校验错误。
3. **属性面板表达参数**：选中的节点、链路、通信域或运行参数的详细编辑。
4. **实验上下文表达生命周期**：项目、切片、凭据、运行、回放和证据，不塞进拓扑卡片。

当前截图中的“超级节点 su0 · node0”同时包住 GPU，又在同一张 GPU 卡片上显示“跨网络 so0”。这把**设备所有权**和**通信端点参与范围**画成了两套嵌套归属，用户自然会理解为一张卡属于两个超级节点。多条跨组虚线又直接连接卡片，形成线团。这个表现既不符合后端语义，也不符合常见拓扑编辑器的使用习惯。

TileSim 应把 `devices[].group_id` 作为设备唯一的计算组归属，把 `domains[].member_devices` 和 `links[].domain_id` 作为通信关系或端点范围。通信域可以引用设备，但不应再次生成设备容器或复制设备卡片。

## 对当前 TileSim 的语义判定

### 1. 设备归属只有一层

- `devices[].group_id`：设备所属的计算组。每张设备卡只能出现一次，并且只能有一个计算组归属。
- 计算组可以在画布上显示为一个超级节点/组框，组内显示其设备。
- `scale_up` 和 `scale_out` 是通信类型或通信域语义，不是第二套设备所有权。

### 2. 通信域不是设备容器

- `domains[].member_devices` 是后端定义的通信端点范围；它可以与计算组成员产生交集。
- 这种交集不应在画布上复制设备卡片，也不应画出“设备属于两个超级节点”的视觉效果。
- 选中通信域时，应在右侧 inspector 或底部关系表显示端点列表；画布只高亮相关计算组和通道。

### 3. 链路要按层级汇总

- 组内链路：在计算组内部显示为轻量的纵向/局部连接，默认不把每条端点线拉到整个画布。
- 组间链路：先汇总成计算组到计算组的通道；用户选中通道后，再在关系表查看具体端点对。
- 通道标签显示通信类型和数量即可，例如“横向扩展 · 4 条端点连接”；带宽、时延、模块绑定等参数放在“互联参数”页或 inspector。
- 只有当用户进入“端点明细”模式时，才显示具体设备之间的线，并提供过滤、聚焦和返回组级视图的入口。

### 4. 当前契约的代码证据

- Bridge 校验器只接受设备字段 `device_id`、`device_type`、`group_id`；未知字段会被拒绝（[`bridge/contracts/validation.py:546-559`](../../bridge/contracts/validation.py#L546)）。
- Bridge 只接受 `scale_up` 和 `scale_out` 两种 `module_kind`/`domain_type`，通信域必须带 `member_devices`（[`bridge/contracts/validation.py:568-677`](../../bridge/contracts/validation.py#L568)）。
- 前端当前的分组投影也明确把 `group_id` 作为唯一 ownership key，并把通信域端点集合视为不产生第二个 owner 的范围（[`topology-supernodes.ts:3-7`](../../src/features/run-experiment/topology-supernodes.ts#L3)）。
- 当前连接判定在同组端点寻找 `scale_up`，跨组端点寻找 `scale_out`；找不到明确覆盖关系时 fail closed（[`topology-supernodes.ts:52-107`](../../src/features/run-experiment/topology-supernodes.ts#L52)）。

## TileSim 建议的目标页面

### 实验设置页的工作流

```text
实验上下文
  ├─ 资源与计算组       （设备清单、唯一 group_id、添加节点）
  ├─ 拓扑关系           （组内结构、组间通道、连接工具）
  ├─ 互联参数           （scale_up / scale_out 参数、模块绑定）
  ├─ 请求与运行参数     （请求、运行时策略、授权字段）
  └─ 校验与提交         （后端能力、引用完整性、硬约束）

运行后
  ├─ 结果与证据
  └─ 执行回放           （时间轴、事件、已报告路径、拓扑空间投影）
```

### 拓扑编辑工作区

```text
┌──────────────┬──────────────────────────────┬──────────────────┐
│ 资源清单     │ 计算组拓扑画布               │ 选中对象 Inspector │
│              │                              │                  │
│ 搜索/筛选    │  [计算组 A] ──横向通道── [计算组 B] │ 类型、ID、归属     │
│ + 新增节点   │    GPU GPU                 │ 端点/链路明细      │
│ GPU          │    NIC                     │ 校验结果           │
│ CPU 主机     │                              │                  │
│ NIC/交换机…  │  组内连接按需展开             │                  │
└──────────────┴──────────────────────────────┴──────────────────┘
```

具体交互：

1. 左侧清单提供后端能力目录允许的节点类型；新增后先进入清单，再出现在画布。没有已发布能力时，按钮禁用并说明原因。
2. 画布默认显示**计算组级别**，组框标题只显示组 ID、设备数和组内通信状态，不显示 `su0/so0` 这种会混淆层级的域标签。
3. 点击设备只选中该设备并打开 inspector；不会把设备复制到通信域框中。
4. 点击组间通道显示通信域、端点数量和已报告状态；点击“端点明细”才展开设备级关系表。
5. 节点参数、链路参数和通信域参数都在 inspector 或独立“互联参数”页编辑；画布卡片只保留身份、类型、组和状态。
6. 清单、画布和 inspector 共用同一个 canonical topology JSON；任何视图都不能形成第二份拓扑事实。

### 创建域的正常人用法

用户不应先被要求决定“这是 so 域还是 su 域”。建议改为：

1. 用户先选择“添加通信连接/通信域”。
2. 选择连接两端：同一计算组内，或两个不同计算组之间。
3. 前端根据后端连接规则给出通信类型建议（组内为 `scale_up`，跨组为 `scale_out`）；类型是解释和校验结果，不是第一步的概念负担。
4. 用户确认端点后，在 inspector 中编辑该连接允许的参数。
5. 如果后端允许覆盖或特殊端点，显示为“端点范围”或“例外”，不能改变设备的唯一计算组归属。

这样用户的心智模型是“我把这些节点连起来”，而不是“我先创建一个抽象 so 容器，再猜哪些卡属于它”。

## 不应继续出现的视觉模式

- 同一设备在多个超级节点框中重复渲染。
- 组框标题、设备卡片和链路标签同时显示 `su0`/`so0`，让域 ID 看起来像设备归属。
- 默认把所有端点对画成跨越整个画布的弧线。
- 把带宽、时延、模块绑定、集合算法或其他互联参数放进设备卡片。
- 使用 router、storage 或其他未出现在后端能力目录的类型作为新增节点选项。
- 用拓扑配置推断执行回放中的真实路径、数据包或流动过程。

## 视觉与交互验收标准

- **唯一归属**：任意设备在画布上只出现一次，且只显示一个计算组归属。
- **关系可读**：默认视图最多显示组级通道；端点级连线必须由用户主动展开。
- **参数隔离**：拓扑画布不承载互联参数编辑；选中对象才能看到相关参数。
- **能力闭世界**：新增节点和连接方式来自后端 descriptor/contract；未发布能力不显示为可选项。
- **可追溯**：画布、清单、关系表和 inspector 都能回到同一个 JSON Pointer/对象 ID。
- **回放分离**：回放使用后端已报告的事件和路径；时间轴与拓扑空间投影联动，但不把配置图变成伪实时仿真。
- **可恢复**：空拓扑、单组、多组、无通信域、端点交集、非法引用和后端能力缺失都有明确状态，而不是空白画布或重复卡片。

## 调研来源与事实边界

本调研只提取公开产品的页面组织和交互模式，不把第三方产品的设备类型、协议能力或动画结果移植为 TileSim 后端能力。TileSim 的可选节点、连接类型、参数字段和回放证据仍以当前 Bridge descriptor、JSON Schema、后端 topology contract 和已报告 artifact 为准。
