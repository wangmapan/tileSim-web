# TileSim Web 易用化界面改造报告

日期：2026-11-06  
目标：在不改变后端契约、证据边界、回放模块和助手能力的前提下，减少信息堆叠，重建清晰的实验配置与结果阅读工作流。

## 1. 改造结论

当前问题是页面职责和信息层级混在一起：同一页面同时承担配置、解释、契约审计、原始 JSON、校验、证据和操作入口。页面因此出现大量重复的小字、嵌套卡片、重复状态和互相竞争的重点。

本次改造采用“少量首要信息 + 明确操作 + 按需详情”的原则：

- 每个页面只回答一个主要问题。
- 首屏只显示用户当前必须做决定的信息。
- 详细证据、契约字段、原始 JSON 和长解释移入折叠面板、抽屉或独立详情页。
- 后端没有报告的内容继续显示为未覆盖/未报告，不用前端推断填充。
- 视觉分组只来自 canonical 数据模型，不能为美观创造新的实体或归属。

不追求“页面上显示更多”，而追求用户能在 5 秒内知道：当前在哪里、下一步做什么、哪里有问题、提交会产生什么。

## 3. 后端事实与不可违反的 UI 语义

Bridge 当前 topology 校验器（`bridge/contracts/validation.py`）只接受：

- 设备：`device_id`、`device_type`、`group_id`。
- 通信模块：`module_kind ∈ {scale_up, scale_out}`。
- 通信域：`domain_id`、`domain_type ∈ {scale_up, scale_out}`、`member_devices`、`module_binding` 等已发布字段。
- 链路：`src_device`、`dst_device`、`domain_id` 以及已发布的可选带宽/时延字段。

因此页面必须遵守：

1. `group_id` 是设备唯一的计算组归属；一个设备只能在一个计算组中出现一次。
2. `domains[].member_devices` 是通信端点范围，不是第二套设备所有权。端点范围和计算组成员可以重叠，但不能复制设备卡片。
3. 同一计算组内的连接表达 `scale_up`，跨计算组的连接表达 `scale_out`；连接类型来自后端规则和当前端点，不让用户先创建抽象的“so 域”或“su 域”。
4. 未被后端能力目录发布的节点类型不出现在“新增节点”列表中；没有可用能力时显示禁用状态和一个简短原因。
5. 带宽、时延、队列、过订阅、模块绑定等属于互联参数或链路详情，不放在设备卡片标题和拓扑组框里。
6. 拓扑配置只表示输入模型；结果页和回放页不得从输入拓扑猜测实际经过路径、数据流或事件。

## 4. 统一信息设计规则

### 4.1 每页只保留三层

**首屏层**：标题、当前对象/运行、一个主结论、一个主操作、最多 4 个关键指标。  
**工作层**：用户当前要编辑或比较的表单、拓扑、表格或图。  
**详情层**：证据引用、Schema identity、JSON Pointer、原始记录、后端解释和完整字段。

现有 `section-kicker`、重复的“当前报告没有……”、重复契约说明和长篇静态帮助文字不能继续占用首屏。需要保留的内容进入统一的详情入口，例如“查看证据”“查看校验”“查看完整配置”。

### 4.2 信息删除规则

直接删除以下类型的重复信息：

- 标题已经表达过的副标题和重复 section-kicker。
- 同一状态在徽标、卡片标题、正文和表格中重复出现。
- 用户完成当前动作不需要阅读的实现细节。
- 对所有用户都相同、且不会改变操作结果的长提示。
- 只为填充空间而存在的“暂无……请到……然后……”小字；改为真正的空状态动作。

以下内容不能删除，只能压缩或移入详情：

- 错误、阻断提交的硬约束、能力缺失和引用错误。
- `0`、missing、not reported、unsupported、not applicable 等不同状态。
- 数据来源、证据范围、artifact identity 和 provenance。
- 会影响用户决定的请求值/解析值、requested/resolved fidelity、真实/synthetic 来源。

### 4.3 视觉规则

- 采用浅色/深色现有 token，不新增渐变、玻璃效果、发光、装饰性大图和无意义图标。
- 减少嵌套卡片；同一层级优先使用分隔线、表格或留白。
- 使用一个明确的 accent 表示当前选择，语义色只表示状态和风险。
- 页面宽度优先给工作区；长文本不在每个卡片中重复。
- 所有折叠、抽屉和删除的详情必须可键盘访问，并尊重 reduced motion。

## 5. 页面改造方案

### 5.1 全局 Shell 与导航

目标：用户一眼知道自己在“配置”“结果”还是“证据”。

- 保留当前路由，不改变深链和助手上下文发布机制。
- 将主导航按工作流分成：**配置实验**、**查看结果**、**深入证据**。视觉上用组标题或分隔线，不增加新路由。
- 顶部只保留当前运行/实验名称、数据状态和一个主动作；Bridge/schema 细节放在状态抽屉。
- 删除导航项旁边的解释长句和重复状态小字。
- 运行不存在时，结果页显示一个明确的“去配置实验”动作，不展示空的结果卡栈。

### 5.2 ExperimentView：改成五步配置流

现有页面把模块导航、结构化表单、JSON、拓扑图和提交说明同时展开。改为以下五步，仍复用现有数据和提交逻辑：

1. **场景**：实验名称、输入来源、运行模式；只显示必要的身份信息。
2. **资源**：设备清单和计算组；新增设备、设备类型、唯一 `group_id`。
3. **拓扑**：计算组画布、组内连接、组间通道；不显示模块绑定参数。
4. **互联与请求**：通信域、模块绑定、Fabric 参数、请求和运行参数；按后端能力显示字段。
5. **检查并提交**：汇总错误、硬约束、关键配置摘要和提交按钮。

每步只显示当前编辑内容。JSON 输入保留为“高级 JSON”入口，默认折叠；不能同时显示结构化编辑器和完整 JSON 文本。

页面底部固定一个轻量状态条：`可提交`、`需要修正 N 项` 或 `能力未发布`。不要在每个组件重复写相同错误。

### 5.3 拓扑编辑器：本次改造重点

目标布局：

```text
┌─────────────┬──────────────────────────┬──────────────────┐
│ 资源清单    │ 计算组拓扑画布           │ 选中对象          │
│ 搜索/新增   │ [组 A] ──组间通道── [组 B] │ 设备/通道/域属性   │
│ GPU/CPU/NIC │ 设备只出现一次            │ 端点明细与校验     │
└─────────────┴──────────────────────────┴──────────────────┘
```

实施规则：

- 左侧资源清单是唯一新增节点入口，来源是 `topologyNodeTypesFromCapabilities`；未发布能力不展示。
- 中央默认是计算组级别视图。每个组框显示组 ID、设备数和连接状态；不显示 `su0`/`so0` 作为设备归属。
- 每个设备只渲染一次；卡片只显示 ID、类型、计算组和必要状态。
- 同组连接可在组内显示为短线；跨组连接默认汇总成组间通道，标签为“横向扩展 · N 条连接”。
- 选中组间通道后，右侧显示通信域、端点数量、具体端点对和链路状态；端点明细用表格，不默认画满屏弧线。
- 选中设备后只显示设备 inspector；选中通信域后显示端点范围，不复制设备卡片。
- “新增通信连接”先让用户选择端点或计算组，再根据同组/跨组关系推荐 `scale_up`/`scale_out`。用户不需要在第一步决定域类型。
- 互联参数、模块绑定、带宽、时延、队列等全部移至第四步或 inspector。
- 删除画布上长期显示的语义说明段落、重复 legend 和每条线的长文本；保留一个简短的“查看规则”入口。
- 空拓扑只有一个主动作“从能力目录添加节点”；无连接只有一个主动作“选择两个节点创建连接”。

### 5.4 Overview

首屏回答“这次运行最重要的结论是什么”：

- 主结论：瓶颈/状态/未提供。
- 四个关键指标：吞吐、TTFT P95、TPOT P95、端到端 P95；沿用现有真实性和 availability 语义。
- 一个简化的执行链路或资源观察区。
- 证据、原始工件、完整网络观测移入“查看详情”。

删除首屏长的技术解释、重复 provenance 文字和空数据的多层卡片；错误和未报告状态必须保留为单一明确空态。

### 5.5 Fabric

首屏回答“网络是否是主要问题，哪一个通信范围最值得看”：

- 顶部只放主通信等待、主导通信域和一条结论。
- 通信域比较使用一张紧凑表格，默认列：域名、类型、占用/等待、状态。
- 端点、拓扑 contract、证据 Pointer 和完整请求贡献放入选中域详情。
- 删除重复的“网络观测/逐项比较/通信范围详情”小标题堆叠；用一个页面标题和一个结果表承载。

### 5.6 Metrics

首屏保留关键指标和请求级结果表；等待归因、设备参与、PD 分离和完整证据改为按需展开。

- 关键指标最多四项。
- 请求表默认只显示 request ID、主要延迟、吞吐/状态、证据入口。
- unavailable、not covered、expected absence 仍需明确显示，不能用空白隐藏。
- 解释性段落改为表格列头帮助或详情抽屉。

### 5.7 Execution（不含回放）

保留请求执行路线作为主视觉，但只显示当前选中层的核心信息。层详情、检查、归因和记录统一为折叠区；不要在同一屏同时打开所有层的长解释。

回放仍保持现状和现有证据边界，本报告不改回放组件、时间轴或动画逻辑。

### 5.8 Design Space、History、Validation、Raw Evidence

- Design Space：首屏显示候选数量、可比较范围、排名/Pareto 结果；完整候选证据折叠。
- History：首屏搜索、运行列表和选择对比；删除操作和永久删除风险留在确认层。
- Validation：先显示通过/失败总览和阻断项；完整规则和 Pointer 详情折叠。
- Raw Evidence：维持原始 JSON 的专业能力，但默认聚焦选中 Pointer/工件，不在其他页面重复渲染完整 JSON。

## 6. 组件和文案改造规则

- 统一使用“标题 + 一句话结论 + 工作区 + 详情入口”结构。
- `section-kicker` 只在真正需要区分上下文时保留；同一页面最多两处。
- 将“当前后端……”这类实现说明改成短状态标签，例如“能力未发布”“未报告”“仅配置”。
- 将长帮助文本改为 `InlineHelp` 或详情抽屉；首屏不超过两行。
- 空态必须包含原因和一个动作，不写三段背景说明。
- 设备类型、通信类型、状态和证据来源使用统一 badge，不重复写同义词。
- 不用颜色单独表达 availability；保留文字和可访问名称。

## 8. 验收矩阵

### 语义验收

- 任意设备在画布中只出现一次。
- 任意设备只显示一个 `group_id` 归属。
- `scale_out.member_devices` 的重叠不会生成第二个设备容器。
- 同组连接自动指向 `scale_up`，跨组连接自动指向 `scale_out`；无明确域时拒绝提交。
- 新增节点列表与能力目录交集一致，未发布类型不可选。
- 互联参数不出现在设备卡片和组框标题中。

### 易用性验收

- 用户进入实验设置后能看到当前步骤和下一步。
- 新增节点、创建连接、编辑参数、检查并提交各只有一个明确主入口。
- 首屏不出现重复的小字解释和同一状态的多处重复。
- 空态都能说明原因并提供下一步动作。
- 组级视图不出现交叉线团；端点详情可按需展开。

### 证据与回归验收

- `0`、missing、not reported、unsupported、not applicable 仍可区分。
- 不新增或升级任何模拟/真实/生产证据声明。
- 回放和助手组件、契约、查询键、上下文发布不发生回归。
- `pnpm contracts:check`、`pnpm docs:check`、`pnpm typecheck`、相关 Vitest、相关 Playwright、`pnpm build`、Bridge `py_compile` 和 `git diff --check` 通过。
- 全量既有失败必须单独报告，不得通过修改测试或临时文件掩盖。
